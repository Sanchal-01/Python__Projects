======================================================================
PROJECT NOTES: THE PYTHONEERS PDF MERGER SYSTEM
======================================================================

Overview:
---------
This project is a command-line utility designed to automate the process of combining multiple separate PDF documents into a single, unified PDF file. 
It dynamically interacts with the user to collect file names, sequences them, and leverages the third-party PyPDF2 library to handle the low-level 
file assembly and generation.

The program:
1. Imports the necessary PDF processing class (`PdfWriter`).
2. Collects the total number of files the user intends to merge.
3. Dynamically captures the exact file names via a loop.
4. Appends each document sequentially into an in-memory stack.
5. Complies, saves, and writes out the final structural payload.
6. Safely terminates system processes to prevent data corruption.

----------------------------------------------------------------------
1. DATA STRUCTURE & VARIABLE ANALYSIS
----------------------------------------------------------------------

A. The 'merger' Object:
   - Type: Instance of the `PdfWriter` class.
   - Purpose: Acts as a digital compilation workspace or virtual "folder". 
     Every page of every target PDF file gets systematically loaded and stacked directly inside this object before saving.

B. The 'pdfs' List:
   - Type: 1D List (Flat String Array).
   - Purpose: Stores the text-based names or full storage paths of the PDF files entered by the user (e.g., `['file1.pdf', 'file2.pdf']`).

C. The Loop Variables ('n' and 'i'):
   - Variable 'n': An integer capturing the total loops/inputs needed.
   - Variable 'i': The structural placeholder index generated by `range(0, n)` to safely increment loop tracking.

----------------------------------------------------------------------
2. LOGICAL FLOW & CORE ENGINE (Step-by-Step Breakdown)
----------------------------------------------------------------------

The program processes operations via two distinct sequential phases:

Phase 1: Collecting File Data (First `for` Loop)
   - Step 1: Takes user input(n) and casts it into an integer (`int(...)`) to determine loop parameters.
   - Step 2: Executes a loop `n` times.
   - Step 3: Displays `f"Enter the name of PDF {i + 1}: "`. Adding `1` to the index prevents displaying user-confusing messages like "Enter PDF 0".
   - Step 4: Executes `pdfs.append(name)` to save the input text inside the storage list.

Phase 2: Compiling & Compacting (Second `for` Loop)
   - Step 1: Initiates a loop iterating directly through the string elements of `pdfs`.
   - Step 2: Executes `merger.append(pdf)`. This signals the engine to find the physical file matching that string name, extract its formatting, 
     and link it cleanly onto the end of the compiled data stack.
   - Step 3: Executes `merger.write("New_Merged.pdf")`, committing the memory contents physically onto the local hard disk under that filename.
   - Step 4: Triggers `merger.close()` to release the operating system lock, safely cleaning up RAM allocation.

----------------------------------------------------------------------
3. DRY RUN / WALKTHROUGH WITH 2 FILES
----------------------------------------------------------------------
- User inputs `n = 2`.
- First Loop runs:
  * Iteration 0: Prompts for PDF 1. User inputs "A.pdf". `pdfs` becomes `['A.pdf']`.
  * Iteration 1: Prompts for PDF 2. User inputs "B.pdf". `pdfs` becomes `['A.pdf', 'B.pdf']`.
- Second Loop runs:
  * Item 1 ("A.pdf"): Linked to memory stack.
  * Item 2 ("B.pdf"): Linked directly behind the pages of A.
- Compilation: Engine writes `New_Merged.pdf` containing all pages of A followed by B.
- System cleanup finishes execution.

----------------------------------------------------------------------
4. AREAS FOR POTENTIAL CODE IMPROVEMENT / ROBUSTNESS
----------------------------------------------------------------------
If we want to upgrade this codebase in the future, consider adding these solutions:
1. File Verification (FileNotFoundError): If a user mistypes a file name, the program immediately crashes. Wrapping `merger.append(pdf)` inside a try-except 
   block can gracefully catch missing files.
2. Extension Auto-Correction: If a user types just "document" instead of "document.pdf", the file loader will fail. We can automatically check 
   and add `.pdf` using string conditioning logic (`if not name.endswith('.pdf'): name += '.pdf'`).
